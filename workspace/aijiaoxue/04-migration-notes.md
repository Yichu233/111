# 建库、迁移与运行交接

2026-10-11。DBMS: SQLite >=3.37；dbms_status: decided_for_teaching_implementation。

## 部署与重启

`python -m app.server --port 18767` 从 app/schema.sql 建8表、6显式索引、3触发器，用 app/data.py 精确灌入样例，默认文件 var/aijiaoxue.sqlite3。`--database 路径` 可选择独立文件。首次建库在目标目录的私有临时文件中事务执行，成功校验后用排他硬链接发布；两个首次启动竞争时只有一个发布成功，另一个验证已存在库。文件系统需支持本地硬链接（本次在Windows NTFS实测）；不支持时明确报错且不生成部分目标库，不自动降级覆盖。

已有文件通过只读连接验证 user_version=1、全部DDL对象签名、quick_check、foreign_key_check和任课角色。数据值可保留人工演示修改，DDL不接受未受支持变更。空文件、损坏文件、版本不符、缺表/触发器均中止，无静默重建；原文件保持不变。

每次请求单独使用SQLite URI mode=ro、query_only=ON、foreign_keys=ON，BEGIN创建一致读取快照，结束关闭。服务端会话不持久化，最多512条、4小时有效，身份切换撤销旧token；重启需重新选择模拟身份。

## 旧系统与回退

旧实现只读Python字典，没有待迁移的学校数据库。本次直接初始化教学样例；原项目和用户未提交更改保存在原处，复制基线的哈希见 docs/upgrade/baseline-manifest.json。对已建立v1库不做滚动schema升级；后续结构变化须先备份、编写显式迁移并测试版本兼容。没有热表ALTER、expand/contract或未经批准的停机数字。

回退先停服务，保留数据库及资料目录副本，再回到原项目运行。不要把删库当作修复错误版本的步骤。若只想重新演示，选择新的 `--database` 路径。

## 一致性与并发

应用无业务写入，只有初次种子事务一个写者；已有数据库各请求只读独立连接。BR-002、BR-008使用FK/PK/UNIQUE，RL-002用INSERT/UPDATE与角色变更trigger，同一SQLite写事务中检查；无A类总量限制、C类不重叠时间段规则。唯一性由数据库而非SELECT-再INSERT保证。并发首建已经双线程实测；真实多人写入和更改资格并发不在本轮工作负载，未做多写者负载测试。

SQLite busy/读取错误返回503，页面清除失败内容后可重试；不自动重放任何业务写入。事务超时5秒是本地实现参数，不是学校SLA。出现真正用户写入、远程共享文件、多机器服务时必须重评引擎和隔离策略。

## 备份与耐久性

本轮只有模拟数据；生产RPO、RTO、保留期没有提供，不能承诺。可停服务后复制完整sqlite3文件及fixtures目录到另一路径保存；运行中备份须用SQLite backup API，不能假设复制活跃写入文件是可靠备份。restore drill: **not tested**；重启持久化测试已通过，但它不等于备份恢复演练。无副本、故障转移或外部发送动作；无read-after-write业务。仅一个本地写者用于初始化。

## 运行依赖和作业

没有schema依赖的定时任务、聚合刷新、TTL清扫、分区任务或归档任务。进程会话过期检查在请求时执行，新会话建立时清理过期记录，有容量上限；进程退出会话丢失。文件读取失败按资源状态/来源错误返回，可更正对应本地资料后重试。无自动维护资料来源的业务流程。

## 安全与可移植性

仅模拟姓名和教学资料，无密码、真实个人信息或生产认证承诺。OS文件权限属于本机使用者；HTTP不提供写入口。角色/系范围、文件存在性、未知含义仍由应用执行。SQLite特有实现是STRICT、PRAGMA、只读URI及RAISE触发器语法；业务的两条数据库BR可迁移至常见FK/UNIQUE，不因分区或引擎选择丢失强制能力。没有L4类别规则降级。
