# 爱教学 Sprint 1源码

第15组“查课程”教学原型，承接实验一的8条Must故事。提供课程与具体开课查询、只读教学资源访问、督导事实与来源查阅。全部姓名、课程安排、资料和督导记录均为模拟数据。

## 启动

需要 Python 3.10或更新版本；本次验证环境为Python 3.12.9。应用和必需测试均仅使用标准库，不需要pip、npm或数据库安装。

在项目根目录打开终端：

```powershell
python -m app.server
```

打开 http://127.0.0.1:8000 。终端保持运行，Ctrl+C停止。Windows也可双击 `启动项目.cmd`。若 `python` 不可用而已安装Python Launcher，使用 `py -3 -m app.server`。

端口已占用时使用 `python -m app.server --port 8001`，访问对应地址。默认只监听本机，不需要联网。

## 演示路径

1. 默认“林老师”：秋季只有K01、K02；K01的联合授课只显示一条开课。选择K02后，教学班、教室和专属资料同时变化。
2. K01资源区：R01为课程共用，R02为K01专属；可以实际打开。R04入口失效，R05暂无入口且来源未提供，R06权限不足。
3. 切换“陈老师”：可以查看K01、K03、K04。K03简介未提供；K04没有关联资源。
4. 切换“周老师”：无任课时为空，不残留前一身份的详情。选择“2027春季”也显示空结果。
5. 切换“教学督导”，选择督导记录页签：K01有两条独立事实记录且可以打开来源；K02只有自己的D03；K04显示资料未收全，不推断未督导。
6. 切换“教研室主任”：可查看计算机系开课和模拟受限资料R06。所有模拟身份都不能读取外系K99。

## 测试

```powershell
python -m unittest discover -s tests -v
```

测试自动启动随机本地端口，结束自动关闭；不用先启动应用。覆盖正常路径、异常输入、跨对象访问、服务端权限与会话边界。

可选浏览器测试需Node.js、Playwright和可用的浏览器，它们不属于应用运行依赖。安装：`npm install --no-save playwright`，然后 `npx playwright install chromium`；先启动应用，再执行 `node tests/browser_smoke.cjs`。若已有Edge，可在PowerShell设置 `$env:BROWSER_CHANNEL='msedge'` 使用本机Edge。`BASE_URL`可指定其他端口。截图与结果写入 `artifacts/`。本次实际结果及检查范围见 `docs/测试报告.md`。

## 结构与接口

```text
app/
  server.py       HTTP入口、模拟会话、JSON与受控文件响应
  domain.py       共享授权规则、对象关联、资源状态及督导事实
  data.py         只读模拟课程、开课、任课、资料与记录
  fixtures/       可实际查阅的本地模拟资料和事实来源
  static/         原生HTML、CSS、JavaScript，无CDN依赖
tests/           服务端集成测试与可选浏览器测试
docs/            测试、接口、人工审查和AI开发说明
```

主要接口：`POST /api/demo-session`选择模拟身份；`GET /api/offerings?term_id=…`查开课；`GET /api/offerings/{id}`查详情；其下`/resources`及`/supervision`查询关联信息。资料正文及事实来源通过受控API访问，不能通过静态目录直接读取。详细输入和错误说明见 `docs/接口与数据边界.md`。

## 模拟权限与实现边界

这是本地教学演示，不是生产账号系统。任何使用者都可通过显式的模拟身份选择器切换角色；HttpOnly会话在服务端记录选择，业务API不信任查询参数中的身份。会话4小时到期或服务重启后需要重新选择。身份可切换不代表真实认证；不得用于真实敏感教学数据。

实现采用演示规则：教师仅看本人开课，主任和督导仅看计算机系开课；资源限当前可见开课及资料允许角色；督导事实仅主任和督导可查。具体学校规则尚需业务方确认，此规则不是学校正式授权政策。

只读内存样例无需数据库，重启不会改变数据。不提供资源编辑、上传、评价生成、覆盖率、学生规模、学校接口或真实身份认证。无督导记录不自动等于未督导；暂无入口、失效与权限不足分别表达。

## 分支与人工验收

源码在 `codex/sprint1` 功能分支上开发并保存AI提交。没有把AI自检写成人工审批，也没有自动合入主干。团队须按 `docs/人工审查与验收清单.md` 审查diff、运行和逐条验收后，由实际审查者填写记录并决定合入。自动测试通过仅证明列明的场景，不代表本轮会议已经举行或DoD中的人工审查已完成。

本次AI实际开发过程见 `docs/AI开发过程记录.md`；完整原始互动应同时保留本任务会话，过程摘要不能替代原件。

## 源码包与Git历史

提交包 `第15组_Sprint1源代码.zip` 包含源码、测试、说明、截图证据，以及 `Sprint1-history.bundle`。直接解压即可运行，不依赖Git。若要恢复提交历史，解压后在其他空目录的父目录执行：

```powershell
git clone -b codex/sprint1 Sprint1-history.bundle sprint1-review
```

该操作会创建新的 `sprint1-review` 目录。之后在其中 `git log --oneline`、`git show <提交号>` 审查变更。bundle保留功能分支真实历史；会议材料属于单独交付，不混入本源码包。
