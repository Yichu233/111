# 爱教学 v5：角色任务界面

## 设计前判断
实际对象是教学班的开课档案，涉及课程、学期、任课教师、教学安排、课程共用资料、班级资料、督导事实和来源。教师需要快速进入自己的任课；主任需要跨开课发现信息缺口；督导需要连续切换查阅对象。沿用本地受控只读接口，不增加未经批准的写入业务。

现场颜色联想：校园导视紫、档案纸白、铅笔灰、批注琥珀、教学资料蓝。标志性结构是“教学班档案页签”：让同一课程的不同开课明确可见。
默认模式三项：所有人同一仪表盘、四张等大指标卡、长页堆叠所有详情。本轮分别改为角色首页、可点击问题分布、选课后分栏与页签查阅。

## 视觉与组件方案（编码前）
色彩：品牌紫#543969；正文#302B3B；背景#F5F4F8；纸白#FFFFFF；资料蓝#38689A；提示琥珀#A66B21。字体Segoe UI/Microsoft YaHei UI；中文正文14px、辅助12px、章节20px、主标题30px；左对齐。间距4px基准，控件12–16px，内容24px，章节28px。主操作采用品牌紫，文字、边线、背景按阅读层级区分，非每张卡片都加阴影。

教师：
[我的教学 / 当前学期 / 刷新]
[任课教学班：安排+资料快捷进入             | 周内安排]
[近期访问资料与课程                      | 查阅提醒]
主任：
[开课总览 / 当前授权范围]
[可点选的资料访问分布                     | 需核对开课]
[开课核查预览表：课程/安排/问题/入口]
督导：
[查阅工作台 / 搜索对象]
[教学班列表 30% | 开课档案 70%]
[               | 安排摘要 / 资料 / 已有记录 页签]

组件意图与层次：教师行的主角是课程名及“准备本课”，安排在其下；主任主角是具体问题及开课，分布只帮助筛选；督导主角是选中开课右侧内容，左侧列表负责上下文切换。使用现有按钮、输入、资源行与受控来源函数。内容面白，页签浅紫，输入浅灰；交互使用明显选中态、键盘焦点、展开/收起和结果反馈，减少无效装饰动画。

方案复核：UI/UX Pro Max首次教育设计系统返回营销Hero和绿色方案，不采用；二次data-dense-dashboard查询仅借用数据列表、可筛选指标和紧凑控制区，不复制通用卡片阵列。新方案不靠三种角色换色区分，而靠信息顺序、导航入口和主要交互区分。

## 技能来源与使用
- Interface Design：https://github.com/Dammyjay93/interface-design；已读取其SKILL.md，以焦点、密度、层次和现有组件为准，本轮作为项目设计参考使用，没有安装到全局环境。
- frontend-design：角色任务决定布局，编码前明确视觉系统。
- Taste：不增加假通知、无依据待办、假完成率或无作用按钮。
- UI/UX Pro Max：筛选反馈、键盘焦点、文字对比、可见标签与桌面宽度检查。

## 约束
仅桌面端。所有业务示例仍为模拟数据。保留八条Must、后端权限、读取失败和未知状态，不将无记录当作未督导。个人备忘仍为本机保存。真实校内认证和数据接入尚未实施。
